# Политика бюджета генерации изображений

## Обязательно: очистка метаданных

Каждый слайд проходит **AI Cleaner** (`mcp-kv.ru/ai-delete`) — как в `ai-carousel-natasha`:
- после Runware/Kie генерации
- повторно перед `export_publish_bundle.py` (gate)

Секрет: `carusel-memory/cleaner.env.local` → `AI_CLEANER_API_KEY`

```bash
python scripts/clean_slides_metadata.py --slides-dir carusel-memory/output/slides
```

Export **без** очистки запрещён (только `--skip-metadata-clean` для отладки).


**Статус:** обязательно. Без согласования заказчика — **один** API-вызов на карусель.

## Проблема

Генерация **6 отдельных** слайдов ≈ **6×** стоимость одного master (~$0.41 vs ~$0.07 на medium).  
На 100 каруселях: ~$41 vs ~$7 — недопустимый перерасход.

## Правило

| Действие | Когда |
|----------|--------|
| **1 master → slice** | По умолчанию, всегда |
| **Перегенерация 1 слайда** | Только после QA и явного «переделай слайд N» |
| **6 отдельных генераций** | **Запрещено** без письменного OK заказчика |

## Техническое решение (Runware)

Полоса 6×4:5 в один ряд = 6480×1350, aspect **4.8:1** — **не влезает** (лимит Runware: max edge 3840, aspect ≤ 3:1).

**Рабочий формат — grid 3×2 (один вызов):**

```text
[ slide-01 ][ slide-02 ][ slide-03 ]
[ slide-04 ][ slide-05 ][ slide-06 ]
```

- Master: **3240×2700** (панель 1080×1350) — в пределах лимитов
- После генерации: нарезка → 6 PNG 1080×1350
- Порядок публикации: 01→06 (слева направо, сверху вниз)

## Перед любой генерацией

1. Тексты слайдов согласованы (copywriter PASS)
2. Один промпт master в `CAROUSEL_IMAGE_PROMPT.json`
3. Dry-run размеров в логе
4. **Не** запускать `runware-carousel-gen.py` в режиме per-slide без флага `--approved-multi`
